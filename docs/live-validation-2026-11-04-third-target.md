skip 明细（均为既有边界，非本轮回归）：

- MySQL `xa-suspend` / `xa-join`：服务端以 1398 拒绝 `XA END ... SUSPEND` 与 `XA START ... JOIN`（B01）。
- Oracle `native-nclob`：服务端以 OBE-00902 拒绝 NCLOB 列（S01）。
- 双模式 `change-user`：本轮未提供第二身份，工具按设计跳过（2026-11-03 目标上该场景曾以一次性身份通过）。

本轮新增/首次实库运行的二十三个场景在本目标上**首次实库运行即通过**：

- `extended-types`（MySQL）：VECTOR(3)/SPARSEVECTOR/ARRAY(INT)/ROARINGBITMAP/JSON 的规范文本回读、NULL 行、CHAR/BLOB 元数据、维数拒绝 7600 且无残留行、`[NaN,0,0]→[0,0,0]` 归一化、`rb_from_string` 写入，以及 JSON 内嵌 Unicode 名字在 text/参数化两条路径上的 `JSON_UNQUOTE(JSON_EXTRACT(...))` 提取。
- `geometry`（MySQL）：LINESTRING/POLYGON/MULTIPOINT/GEOMETRYCOLLECTION 四种形状的 SRID-0 文本/字节往返、`ST_SRID` 与 4 字节 SRID 前缀、raw bytes 回绑，以及 SRID 4326 逐形状以 3548 拒绝（另加纯字面量控制）且无残留行。
- `oracle-spatial`（Oracle）：SDO_GEOMETRY 点与多边形的字面量写入、`G.SDO_*` 成员访问、OBJECT/集合解码（嵌套 `SDO_POINT_TYPE`、`SDO_ELEM_INFO_ARRAY`、`SDO_ORDINATE_ARRAY` 精确元素），以及 SRID 4326 以 13029 拒绝且无残留行。
- `oracle-urowid`（Oracle）：900 字符长键使 `ROWID` 伪列返回 >251 字节的扩展 rowid，经复用的 prepared statement 写入 NULL/UROWID/NULL 三行并按值回读，再用 `BEGIN ? := ?; END;` 做 IN OUT 绑定校验。
- `oracle-xml`（Oracle）：`XMLTYPE` 列的服务器规范化文本（含尾部换行）、NULL 行，以及 `XMLTYPE` 数据库类型名与 `string` ScanType 在 text/参数化两条读取路径下一致。
- `oracle-number-scale`（Oracle）：`NUMBER(10,-2)` 写入按百位取整（12345→12300、-12345→-12300、99999999→100000000），`NUMBER(5,8)` 存 0.00012345 读回 `.00012345`；元数据经驱动返回 precision=10/scale=**-2** 与 precision=5/scale=8；10^12 与 0.001 分别触发 1438 且无残留行。本目标 10^11 级值可接受、10^12 被拒，属目标边界记录。
- `mysql-charset`（MySQL）：7 种严格字符集列（cp850/hp8/macroman/swe7/ujis/cp932/eucjpms）逐个建表，文本绑定经服务器转码后 `HEX` 与冻结字节一致，`CONVERT(CAST(? AS BINARY) USING ?)` 写入的原始字节可被 UTF-8 读者读回；把 `character_set_results` 切到该字符集后，text/参数化两条路径的列文本与 `HEX` 均能正确解码（含 PUA 码位）。
- `oracle-binary-float`（Oracle）：`BINARY_FLOAT` 保存 float32 精度的最大有限值、最小正规值、次正规值与 `0.1` 舍入，NaN/±Inf 原样通过，并与精确 `BINARY_DOUBLE` 值同表对照；元数据类型名、`float64` ScanType 与空 decimal size 经文本和参数化两条读取路径核对，另含一行 NULL。
- `mysql-utf16le`（MySQL）：`CONVERT(? USING utf16le)` 的 4 个取值（含 BMP 外代理对、空串、替换字符、重复中文）解码回原 UTF-8，`HEX` 等于精确小端 UTF-16 字节（如 `中😀` → `2D4E3DD800DE`）；字面量路径同值，且结果元数据为 `VARCHAR`/`string`。
- `oracle-synonym`（Oracle）：经视图与其同义词读取、经表同义词写入并回到基表核对；`MetadataSynonyms` 返回唯一的同义词行，OWNER 与 TABLE_OWNER 一致、目标为视图名、CATALOG/DB_LINK 为空（不被伪造）。
- `mysql-enum-set`（MySQL）：`ENUM('a','b','c')`/`SET('x','y','z')` 合法成员逐行回读，`SET` 输入被服务器规范化（`z,y`→`y,z`、`x,x`→`x`），NULL 保持 NULL，非法 `ENUM`/`SET` 成员均以 1265 拒绝且无残留行；两列元数据为 `CHAR`/`string`。
- `mysql-generated-columns`（MySQL）：`B AS (A*2) STORED`、`V AS (A+1) VIRTUAL` 按输入计算（不含显式绑定）、输入 NULL 则生成列为 NULL、`UPDATE` 后两列同步重算，元数据 `INTEGER`/`int64`，显式写入生成列被 3105 拒绝且无残留行。
- `char-padding`（双模式）：`CHAR(5)` 以 `'ab'` 写入后，Oracle 回读补空格的 `'ab   '`、MySQL 回读 `'ab'`（均与服务器实际字节一致，驱动不做裁剪）；`WHERE C='ab'` 与 `RTRIM(C)='ab'` 都匹配 1 行；`VARCHAR`/`VARCHAR2` 不补空格；超长写入 MySQL 1406、Oracle 12899 且无残留行。
- `empty-lob`（双模式）：服务端零长度 LOB 与 SQL NULL 可区分——`sql.Null[[]byte]`/`sql.Null[string]` 对空值返回 valid=true、长度 0，对 NULL 返回 valid=false；裸 `[]byte` 空值长度为 0（实库探针确认非 nil）、NULL 为 nil；`CASE WHEN ... IS NULL` 计数证明 MySQL 仅 NULL 行为 NULL，而 Oracle 中绑定空串/空字节按 Oracle 语义落为 NULL（与显式 `Blob`/`Clob` 定位器路径分工一致）。
- `metadata-patterns`（双模式）：`Metadata` 的 `NamePattern` 是 LIKE 模式——原样传入 `OBT_OFFLINE_WILD_1` 会同时命中 `OBT_OFFLINE_WILDA1`（`_` 通配）、`OBT_OFFLINE_PCTX1` 会命中 `PCT%1`；经 `exactPattern` 转义（`/`、`_`、`%`）后每个名称只命中自身，证明驱动侧转义正确、通配语义未被吞掉。
- `oracle-identity`（Oracle）：`GENERATED BY DEFAULT AS IDENTITY` 隐式插入自增 1，显式插入 100 不推进序列（下一隐式键为 2）；`GENERATED ALWAYS AS IDENTITY` 显式插入以 32795 拒绝且不落地；`MetadataColumns` 把 `DATA_DEFAULT` 为 `SEQUENCE.NEXTVAL` 的列报告为 auto-increment=1，普通列与 `DEFAULT 7` 列保持 NULL（不误报）。
- `metadata-indexes`（双模式）：唯一索引与复合索引在 `MetadataIndexes` 中保留名称、唯一性（0/1）、列顺序与序号（`V`→1、`W`→2），主键索引也被列出；`MetadataServerInfo` 单行返回版本（含 4.4）与模式名（`MYSQL`/`ORACLE`）。
- `metadata-routines`（双模式）：过程与函数在 `MetadataRoutines` 中保持名称与类型（`PROCEDURE`/`FUNCTION`）；过程参数按序返回 `pIn`(1,IN)、`pOut`(2,OUT)；函数额外返回位置 0 的无名 `RETURN` 行，其参数 `pIn`(1,IN) 与数据类型均非空。
- `statement-parameters`（双模式）：`MetadataStatementParameters` 对 `SELECT ?+?`（Oracle 加 `FROM dual`）返回两个匿名占位符：物理/逻辑序号 1、2，`data_type=BIGINT`，`protocol_type=8`、`protocol_direction=0`，`name`/`direction` 为 NULL；`nullable` 仅 Oracle 为 1。同一语句按位置绑定 3/4 得 7，证明占位符可执行。
- （已撤回）`jdbc-escapes`（双模式）：该场景随 Java 专有的 JDBC 转义能力一并删除；保留此条仅为记录当次运行内容。
- `metadata-type-info`（双模式）：`MetadataTypeInfo` 十列内置类型家族 MySQL 29 行 / Oracle 19 行，类别（numeric/character/binary/datetime/interval/lob/rowid）与类型名唯一；抽样断言 `INT(name,precision 10,radix 10,auto 1)`、`DECIMAL(65,0,30,precision,scale)`、`BIT(b',64)`、`DATETIME(0,6)` 与 Oracle `NUMBER(38,-84,127)`、`TIMESTAMP(0,9)`、`ROWID`、`BLOB` 无前后缀。
- `identifier-length`（双模式，**仅离线验证**）：最大长度表名（MySQL 64 / Oracle 128 字符）与 128 字符列名经 DDL、绑定插入、查询及表/列字典均不被截断；超限一个字符由目标以 1059 / 972 拒绝。该场景已注册并有 12 个离线用例，实库验证因目标不可用而**未完成**（见 §6）。
- `views`（双模式）：简单视图在两种模式下可经驱动 `INSERT`/`UPDATE`/`DELETE`，写入落到基表；视图谓词只约束读取——插入 `ID=0` 的行在基表存在、视图不可见；经视图删除后基表仅剩该行；`MetadataTables` 报告 `VIEW` 类型、`MetadataColumns` 返回视图两列且类型名非空。
- `floats`（双模式）：DOUBLE/BINARY_DOUBLE 的 8 个边界行（1.5、1.1、±MaxFloat64、最小次正规、负零、NULL、float32 加宽）按位回读、后续参数不受污染；Oracle 负零与 `TO_BINARY_DOUBLE('-0')` 字面量的 `DUMP` 一致，另以 `TO_CHAR` 交叉核对存储文本。

## 4. 对缺失矩阵的影响

- V13–V17 的验收工具覆盖率提升为实库已验：`extended-types`、`geometry`、`oracle-spatial`、`oracle-urowid`、`oracle-xml`、`oracle-number-scale`、`mysql-charset`、`oracle-binary-float`、`mysql-utf16le`、`oracle-synonym`、`mysql-enum-set`、`mysql-generated-columns`、`char-padding`、`empty-lob`、`metadata-patterns`、`oracle-identity`、`metadata-indexes`、`metadata-routines`、`statement-parameters`、`metadata-type-info`、`views` 场景加上双模式 `floats` 现可作为该目标的回归基线。
- U02/U03（原生 RECORD/ANYDATA）在本目标上再次确认服务端拒绝（B16），仍缺“成功的 wire 依据”，因此保持未实现，不做盲写。
- 未改变的外部边界：MySQL XA SUSPEND/JOIN（B01）、Oracle NCLOB（S01）、RoaringBitmap 直传 bytes（B11）、缺 SRS 的 SRID（3548）、ChangeUser 代理目标（B21，本轮无代理身份）。
- 环境类（ENV）与权限类（A）项仍未覆盖：TLS/mTLS、强制压缩、OBProxy/多节点/OCP、插件/KDC、Linux/macOS 原生协议，以及受限身份/权限组合。

## 6. 目标不可用与待验项（2026-11-04）

在 `views` 全量复验（110/0/5/27）之后、`identifier-length` 实库验证期间，两模式目标开始对任意语句返回 `wire: read after 0 bytes: EOF`，包括 `SELECT 1` 与 `SELECT ob_version()`；2026-11-04 用户告知**数据库服务器已损坏、恢复时间未知**，因此本轮报告不再对该目标安排恢复重试，实库验收顺延到新目标提供后；同一时刻 TCP 2881 仍可建立连接（`Test-NetConnection` True），因此是服务端/转发后端拒绝而非网络不可达。连续 5 次重试（间隔 5 s）与 25 s 后复测均相同。

- 期间一次 MySQL 模式 `identifier-length` 实跑在"表名字典被截断"断言处失败；该次运行与目标开始不可用的时间窗重合，**无法判定是驱动/字典行为还是目标降级**，在目标恢复前不作为驱动缺陷上报，也不作为通过。
- 待目标恢复后需补做：`identifier-length` 与 `topology-sources` 双模式实跑、全量 72 场景复验（预期 112/0/5/27）并更新本节与计数。
